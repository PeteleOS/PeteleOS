LEVEL 2-3 -- DEVICE AND DRIVER MODEL
=====================================

1. AUTOCONF FRAMEWORK (kernel/core/kern/subr_autoconf.c)

  Central mechanism for device discovery and attachment.
  Data: cfdata[] in ioconf.c (generated by config(8) from GENERIC + files.*).
  API: config_init(), config_rootfound("mainbus", ...), config_found(), config_attach().
  Each driver declares cfdriver, cfattach, cfdata via config(8) output.
  Probe/attach: driver probe checks hardware, attach initializes and registers.

2. BUS HIERARCHY (VERIFIED FROM kernel/dev/ AND kernel/arch/)

  Top: mainbus (arch/<arch>/<arch>/mainbus.c)
    -> cpu (arch/<arch>/<arch>/cpu.c)
    -> pci (dev/pci/pci.c) -> ppb (pci bridge), vga_pci, etc.
       -> drivers: if_em.c, if_iwx.c, drm/*, ahci_pci.c, nvme_pci.c, ...
    -> isa (arch/amd64/isa/clock.c, dev/isa/*) -- amd64 only
    -> usb (dev/usb/uhci.c, ohci.c, ehci.c, xhci.c + dev/pci/uhci_pci.c etc.)
    -> scsi/ata/atapiscsi (scsi/scsiconf.c, dev/ata/ata.c)
    -> sdmmc (dev/sdmmc/sdhc.c)
    -> i2c (dev/i2c/*, dev/ic/dwiic.c), spi (dev/spi/*), gpio (dev/gpio/*)
    -> wscons (dev/wscons/*, wsfont/*, rasops/*) -- console
    -> vmm (dev/vmm/*) -- hypervisor
    -> acpi (dev/acpi/*), efi (dev/efi/*), fdt (dev/fdt/*), ofw (dev/ofw/*)
    -> pv (dev/pv/*: virtio, hyperv, xen, vmt) -- paravirtual

  Bus glue per arch (kernel/xmake.lua BUS_GLUE_DIRS):
    amd64: arch/amd64/isa/, arch/amd64/pci/
    arm64/riscv64: arch/<arch>/dev/

3. DRIVER CATEGORIES (SAMPLED FROM generated_manifest.lua 2470 entries)

  Network: dev/pci/if_*.c (em, ix, iwx, bge, re, etc.), dev/ic/*, dev/mii/*,
           dev/usb/*, dev/pv/if_vio.c, dev/pci/drm/* (display also)
  Storage: dev/ic/ahci.c, nvme.c, mfi.c, dev/pci/ahci_pci.c, scsi/sd.c, dev/ata/wd.c
  Graphics: dev/pci/drm/* (i915, radeon, amdgpu with dml/*_fpu.c), rasops, wsfont
  Input: dev/pckbc/*, dev/ic/pckbc.c, dev/wscons, dev/hid/*
  Audio: dev/audio.c, dev/ic/ac97.c, dev/pci/azalia.c, sound cards via dev/pci/*
  Crypto offload: dev/pci/ccp_pci.c, dev/ic/ccp.c, ccp, psp
  Misc: dev/rnd.c (entropy), dev/vnd.c, dev/bio.c, dev/kcov.c, dev/dt/*

4. INTERRUPT MODEL

  MD: arch/<arch>/<arch>/intr.c, apic.c, ioapic.c, lapic.c (amd64),
       intr.c per arch.
  API: intr_establish(), intr_disestablish(), spl* (splhigh, splnet, splbio, etc.
       via vector.S / spl.S on amd64).
  Soft interrupts: kern_softintr.c (softnet, softclock, softtty).
  evcount: subr_evcount.c for interrupt statistics.

5. DMA AND BUS SPACE

  bus_dma.c, bus_space.c (arch MD): bus_dmamap_create, bus_space_map/read/write.
  Used by all DMA drivers (pci, usb, storage).

6. DEVICE FILES AND SWITCH TABLES

  sys/conf.h: bdevsw[], cdevsw[] tables.
  cons.c, cninit.c: console init.
  spec_vnops.c: VFS ops for device nodes.

7. DISPLAY AND CONSOLE

  rasops/*, wsfont/*, dev/videomode/*, dev/ic/pcdisplay*, vga_pci.c
  efifb.c (arch/amd64) for EFI framebuffer.
  wscons: wsdisplay, wskbd, wsmouse.

8. INITIALIZATION ORDER
  autoconf.c: config_init -> mainbus attach -> per-bus enumeration ->
  driver probe -> intr_establish -> device ready. Failures are non-fatal if
  optional (firmware missing, etc. skipped).

9. FIRMWARE
  firmload.c loads firmware blobs. No blobs vendored in resources/ (VERIFIED
  ABSENCE); fetched via fw_update(8) at runtime.

10. REFACTORING NOTES
  Autoconf cfdata is generated and tightly coupled to GENERIC + files.* lists.
  Adding a driver requires editing files.* and rebuilding manifest.
  Interrupt and bus_dma abstractions are leaky (MD differences visible in MI drivers).
