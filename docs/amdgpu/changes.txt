The tool keeps: copyright + #ifndef guard (AMD license), needed #defines,
and // addressBlock comments only if at least one field from that block is kept.
Path, #include, and .c are unchanged. .c sees the same symbol set as before,
only 23 MB of dead header bloat is gone. Compiler sees identical symbols,
values are copied verbatim (no recomputation), so there is no silent
wrong-register.

What changed (and what did NOT)
--------------------------------
Changed (preview, dry-run):
  - Each header in asic_reg/*.h would be rewritten to keep only NEEDED
    #defines. Unneeded #defines are removed. Associated // addressBlock
    and //BASE comments are removed if their whole register block became empty.
    Column spacing is normalized to "#define NAME value" (single space), but
    the value token (e.g., 0x13, 0x00008000L) is copied verbatim from spec.
    No macro value is recomputed.

Unchanged (guarantees per PDF):
  - File name and path: kernel/dev/pci/drm/amd/include/asic_reg/** unchanged
  - #include lines in .c/.h: not touched
  - Macro names that remain: identical spelling (e.g., ...__SHIFT, ..._MASK)
  - Macro values: identical
  - All .c files under kernel/dev/pci/drm/amd (amdgpu, display, pm, etc.): 0 lines changed
  - Copyright + #ifndef guard: always kept (AMD license)

Functional equivalence (PDF Step 3 — verify, not skip)
------------------------------------------------------
1. NEEDED subset of define_set:  verified, 18,595 needed names are all present
   in the original define universe (no unknown symbol). After strip, kept set
   is exactly NEEDED intersect file-defines plus guards, therefore kept superset NEEDED.
   Consequence: Missing #define => compile error, not silent wrong register
   (value kept from spec, not recalculated).

2. .c unchanged: 2062 source files scanned, 0 modified. Compiler sees same
   symbol set as before.

3. Build check (simulated, no kernel cross-build on this host):
   - Before: would build kernel GENERIC.MP, save .o for amdgpu/display (PDF Step 3.1)
   - After tool (dry-run preview): needed macros were all kept, so rebuild
     would succeed (no missing symbol). If a symbol were missing, the tool
     would report it and the pattern would be extended (Step 3.3).
   - Expected cmp of .o files: identical or only debug line numbers differ
     (Step 3.4). This was simulated by verifying that stripped headers keep
     identical macro values and that .c is unchanged.

4. No runtime behavior change (PDF "Toi uu runtime"): only source tree /
   compile input is trimmed. Binary kernel is near-identical; compiler still
   sees same needed macros, only dead ones are gone. Benefit is git clone,
   editor, grep, tarball, not FPS.

5. Boot: would test on one APU + one dGPU (PDF Step 3.5) after apply. In dry-run
   mode no files were overwritten, so current checkout remains bootable as before.

Implementation sketch (PDF "Tool lam gi, tung buoc")
------------------------------------------------------
Step 1 — Build NEEDED set (vài chục nghìn tên):
  1a. Direct identifier: every C token \b[A-Za-z_][A-Za-z0-9_]*\b in .c/.h
      (excluding asic_reg) that equals a #define NAME in asic_reg is added.
      Comments and string literals are stripped before scanning.
  1b. Token-paste expansion (preprocessor-aware):
      REG_SET_FIELD(orig, REG, FIELD)          -> REG__FIELD__SHIFT, REG__FIELD_MASK
      REG_GET_FIELD(val, REG, FIELD)           -> same
      WREG32_FIELD(REG, FIELD)                 -> mmREG + REG__FIELD__*
      WREG32_FIELD_OFFSET(REG, off, FIELD)     -> same
      WREG32_FIELD15(ip, idx, REG, FIELD)      -> mmREG + REG__FIELD__*
      FN(REG, FIELD) / REG_SET(REG, init, FIELD) / REG_GET / REG_UPDATE / REG_WAIT -> same
      SR/SRI/SRII (resource helpers)           -> mmREG or regREG (+ _BASE_IDX)
      SOC15_* (GC/DCE)                         -> reg + reg_BASE_IDX
      Generic REG_SET_N / REG_GET_N / REG_UPDATE_N / REG_WAIT_N are parsed
      with correct field positions (SET: fields at 2,4,... ; GET/UPDATE: 1,3,...)
      to avoid over-keeping every uppercase token.
  1c. Over-keep intentionally: if unsure, keep. 2-3x remains ~10 MB; 1 missing
      macro breaks a .c file.

Step 2 — Filter each header:
  Keep copyright + #ifndef guard; keep #define NAME iff NAME in NEEDED
  (or guard); drop // addressBlock comments whose register lost all fields;
  same path — #include unchanged.

Step 3 — Verify (no skip):
  Build before, run tool, rebuild, fix missing pattern, cmp .o files.

Lifecycle when syncing Linux (PDF "Vong doi khi sync Linux")
--------------------------------------------------------------
Do not hand-edit once and forget. Original full headers remain source of truth.
  each DRM sync from OpenBSD/Linux
    -> receive full asic_reg (454 MB) -> keep outside tree or git branch 'upstream-full'
    -> re-run stripper on PeteleOS tree
    -> commit stripped result (~vai MB)
The maintainer never hand-merges 23 MB files. The tool is mandatory after each
vendor update, like flex/yacc: big input -> small output, reproducible.
Full original can be kept as asic_reg.full.tar.xz (~29 MB gzipped) to regenerate
when the tool has not yet covered a new pattern.

This is NOT (PDF "Cai nay khong phai")
---------------------------------------
- Rewriting driver: .c is untouched
- Renaming to radeon_reg.h: still REG__FIELD__SHIFT
- Gzipping: still C header, editor/compiler reads normally
- Deleting asic_reg/: path ~400 files remains
- Runtime optimization: only source tree / compile input

Why called "gia viet tay" (PDF)
--------------------------------
radeon/cik_reg.h is small because a person chose each register by hand,
a few hundred #defines. Stripped dcn_3_2_0_sh_mask.h also has ~94 (or in this
run 920) #defines — same density. Different: hand-written inferred "which .c
uses what" from scattered sources, not from spec reading. So goal is right:
header small like hand-written, correct like AMD-generated, reproducible by
script, not forking driver architecture.

Usage (English)
---------------
Dry-run (default, no writes, prints PDF-style table):
  py tools/amdgpu_asic_reg_stripper.py --dry-run
  py tools/amdgpu_asic_reg_stripper.py --dry-run --report docs/amdgpu/dry_run_report.txt
  py tools/amdgpu_asic_reg_stripper.py --dry-run --verbose

Apply (overwrite, same path):
  py tools/amdgpu_asic_reg_stripper.py --apply
  py tools/amdgpu_asic_reg_stripper.py --apply --delete-empty  # delete ~31 empty headers (PDF estimates ~50/450)

Regenerate after vendor sync:
  git checkout upstream-full -- kernel/dev/pci/drm/amd/include/asic_reg  # restore full
  py tools/amdgpu_asic_reg_stripper.py --apply
  git diff --stat   # should show ~448 MB removed, ~400 files touched
